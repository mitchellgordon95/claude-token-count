Method

A fresh Claude Pro account is driven through headless Claude Code with tools disabled and a one-line system prompt. Each run holds the token mix constant: output runs ask for long essays from tiny prompts, input runs send huge uncached prompts and ask for one word, cache runs resend the same huge prompt so it hits the prompt cache.

After every call we read the same usage endpoint Claude Code's /usage uses, which reports whole-percent utilization of the 5-hour and weekly limits. A partial run stops after the meter rises a set amount and extrapolates to 100%. Because the meter is integer-valued, we also fit a line through every tick-up (the step fit), which is more precise than a single ratio. A full run keeps going until the account is rate-limited, so the window total is measured outright.

Every call also reports its API-list-price cost. If the plan is a cost-weighted budget, percent-per-dollar should be the same across output, input, and cache runs; that number is shown in the table so the hypothesis is checkable.

Data lives as JSON in the repo: runs.json, latest.json, raw per-call samples under data/raw/.
